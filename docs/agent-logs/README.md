# Agent 操作日志规范

本目录保存 AI 辅助编码的过程记录，属于考核交付物（「AI 工具的利用」评审维度的证据）。

## 文件分工

| 文件 | 写入者 | 写法 |
|---|---|---|
| `<github-id>.md`（5 份，每位协作者 1 份） | 该协作者本人的代理 | 只追加到文件末尾，按时间顺序 |
| `SUMMARY.md` | 仅 reviewer 的代理 | 每合并一个 PR 追加一条汇总 |

每份文件只有一个写入者，因此不同协作者的 PR 之间不会产生日志冲突。

> [!IMPORTANT]
> 已提交的条目不改写、不删除。写错时追加一条新条目，在「备注」里写明更正的是哪条编号。

## 何时写

- 每次代理会话产出了提交，就写一条；同一 PR 可以对应多条。
- 只做调研、未产出提交的会话，若形成了影响设计的结论，也写一条。
- 日志条目与代码改动放在**同一个 PR** 里提交。

## 条目模板

复制以下模板追加到自己文件末尾。编号 `NN` 为当天序号，从 `01` 开始。

```markdown
### LOG-<github-id>-YYYYMMDD-NN

- **时间**：YYYY-MM-DD HH:MM（+08:00）
- **工具/模型**：如 `Claude Code / <模型名>`、`Codex / <模型名>`
- **模块 / 分支 / PR**：M2 / `feat/m2-stats-api` / #12（PR 未建时写「待建」，建好后不必回填）
- **任务**：一句话说明本次要解决什么
- **关键提示词**：人给代理的核心指令摘要（1–3 条，不贴整段对话，不含密钥与个人信息）
- **代理做了什么**：
  - 修改/新增的文件与要点
- **决策**：做了哪些取舍、为什么；向人确认过的问题与结论
- **验证**：运行的命令及结果（如 `pnpm -r test` 通过 42 项）
- **人工审核**：采纳 / 修改后采纳 / 拒绝，及原因
- **遗留问题**：未完成项、已知风险；没有写「无」
```

完成标准：模板每个字段都有内容；「验证」写的是真实运行过的命令和结果。

## Reviewer 汇总流程

仅 reviewer 的代理执行。每合并一个 PR 后：

1. 读该 PR 中新增的个人日志条目（`git diff <merge-base>..<merge-commit> -- docs/agent-logs/`）。
2. 检查条目是否齐全（模板字段完整、编号格式正确、无密钥与个人信息）。缺失时在 PR 中留言要求作者补一条新条目，不代为修改他人日志。
3. 在 `SUMMARY.md` 末尾按下方格式追加一条，并更新文件顶部「进度看板」。
4. 汇总提交单独成 commit：`docs(agent-logs): summarize #<PR号>`。

完成标准：本周所有已合并 PR 在 `SUMMARY.md` 中都有对应条目，且每条都链接到至少一个个人日志编号。

### 汇总条目格式

```markdown
### #<PR号> <PR 标题>

- **合并时间**：YYYY-MM-DD
- **作者 / 模块**：`<github-id>` / M2
- **关联日志**：LOG-xxx-YYYYMMDD-01、LOG-xxx-YYYYMMDD-02
- **改动摘要**：1–3 句
- **契约 / 术语影响**：无 / 契约 v1 新增字段 `xxx` / GLOSSARY 新增术语 `xxx`
- **评审意见**：通过 / 修改后通过，要点
- **后续事项**：无 / 具体事项及负责人
```
