# AI 辅助编码规范（面向协作者）

> 本文约束「人」如何使用 AI 编码代理；代理自身遵守的规则见根目录 [AGENTS.md](../AGENTS.md)。

## 1. 基本立场

- 代理产出的代码由**发起 PR 的人**负责，与手写代码同等标准审查。答辩时每位成员需要能讲清自己模块的设计与实现，包括 AI 写的部分。
- AI 辅助过程是交付物：每次产出提交的代理会话都要在个人日志中留档（[格式](agent-logs/README.md)）。

## 2. 推荐做法

- **先给上下文再提需求**：让代理读 `AGENTS.md`、相关契约章节与 GLOSSARY，再描述任务；复杂任务先让代理出方案，确认后再动手。
- **小步提交**：一次会话聚焦一个可验证的目标，完成后跑测试、写日志、提交。
- **让代理写测试**：要求它先写或同步写测试，并亲自运行；人工核对测试确实覆盖了需求而非迎合实现。
- **核对外部 API 用法**：代理给出的 SDK 调用、参数名、模型名，以服务商官方文档为准再采纳。
- **提示词调优留痕**：调整 LLM / OCR 提示词时，在日志中记录修改前后的输入样例与效果差异，这是「AI 能力使用」评审的直接证据。

## 3. 禁止事项

| 禁止 | 原因 |
|---|---|
| 把真实 API Key、`.env` 内容、他人个人信息粘贴进对话 | 泄露风险；对话可能被记录 |
| 未经阅读直接提交代理生成的大段代码 | 无法通过答辩追问，也易引入缺陷 |
| 让代理绕过契约、自行约定跨模块字段 | 破坏模块边界，联调返工 |
| 让代理修改他人模块或他人日志而不告知对方 | 产生冲突与责任不清 |
| 用 AI 伪造或事后批量补写日志 | 日志失去可信度 |
| 引入许可证不明或来源不明的代码片段 | 开源合规 |

## 4. 工具选择

团队不限定具体工具（Claude Code、Codex、Cursor、Antigravity 等均可），但：

- 工具需能读取仓库根目录的 `AGENTS.md`（Claude Code 通过 `CLAUDE.md` 导入）；不支持的工具需在会话开头手动提供其内容。
- 日志「工具/模型」字段如实填写，便于复盘不同工具的效果。
