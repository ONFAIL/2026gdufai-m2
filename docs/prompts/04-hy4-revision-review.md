## 三、新发现的问题（非阻塞）

**1. Markdown 管道符未转义，表格会被切开**

- 位置：D 节第 2 表 `modality` 行 —— 原文「`"text"` | `"voice"` | `"image"`」
- 位置：建议新增的字段/码表 `categoryId` 行 —— 原文「`number | null`」
- 问题：两处 `|` 未转义，标准 Markdown 表格会多切出列，该单元格在渲染后错位。
- 依据：方案自身排版纪律（表格需可渲染）
- 影响：仅影响阅读，不影响实现；但 02 要求逐字引用时，错位的表格会让人引错字段。
- 最小改法：把 `|` 写成 `\|`，或把枚举分隔符改成「/」。

**2. 「仍要提交」删除后，`DUPLICATE_RECORD` 的重发键未明确**

- 位置：D 节第 3 表「`DUPLICATE_RECORD`」行 —— 原文「提供「修改时间/商户后重发」与「放弃录入（关闭卡片）」两个按钮」
- 问题：该反馈码的契约触发条件是「幂等键重复」，但方案给出的是「修改后重发」路径；若重发仍用原 `idempotencyKey`，会再次命中重复。契约 §1.2 又要求追问重发「同 `idempotencyKey`」，两处要求在该场景下相互拉扯。
- 依据：契约 §1.5（触发条件「幂等键重复」）与 §1.2（同 key 重发）的内在张力
- 影响：实现时可能选错键策略，导致用户永远卡在重复提示里。
- 最小改法：在 D 节第 3 表补一句——该场景下重发是否更换 `idempotencyKey`，需后端书面确认后再定。
