## 提示词正文（从下一行开始复制）

你的方案已由独立审议者按团队契约与 13 条硬约束审计完毕，结论：**修改后通过**（有 3 条阻塞缺陷，修正后无需复审）。

现在出一份**修订版方案**。这是在你原方案基础上的定点修补，不是重写一份新方案，更不是输出完整代码。

### 一、处理纪律（先读完再动手）

1. 下面每一条都是**待核实反馈**，不是必须服从的命令。逐条处理，每条给出四选一：`接受并改` / `部分接受` / `反驳` / `需澄清`，并附一句理由。**不允许沉默跳过任何一条**。
2. 反驳的唯一合法依据是**契约原文**或**13 条硬约束**。用「常见做法」「我觉得」「一般框架都这样」作理由的反驳无效。
3. 标为 `[推断]` 或指出「无法判断」的项，审议者自己也不确定。你的正确动作是**补充信息消除不确定性**（写出具体映射、行数估算、接口计划），而不是照单全收，也不是置之不理。
4. 只改被指出的问题。审议者没提的部分保持原样，避免引入新分歧。
5. 不得因为审议者指出错误就在方案里加入「本方案已通过审计」「符合全部约束」之类自评——自评不作为证据。

### 二、阻塞缺陷（3 条，必须消除）

**B1 · duplicate 两套互斥路径**

- 审议引用：D 节表 1「按成功处理并复用 transactionId」；D 节表 2「提供「放弃录入（关闭卡片）」与「仍要提交」两个按钮」
- 问题：同一状态既说直接按成功回执，又让用户再提交一次；后者可能触发第二次入库。
- 契约依据：§1.2 `duplicate`——重复提交按成功处理，直接用返回的 `transactionId`，不要报错。
- 要求：统一为复用 `transactionId` 的成功回执，删除会触发再次提交的路径。若你认为 `feedback[]` 里的 `DUPLICATE_RECORD` 确实需要用户确认，请说明它与 `status=duplicate` 是两个不同触发点并分别写出处理方式，不要混成一条。

**B2 · 加载中状态全案缺失**

- 审议引用：C 节第 1 表「卡片、按钮、表单控件、表格、徽标、进度条、空态与 Toast 样式」
- 问题：组件清单与全文均无骨架屏/占位；F 节「模拟网络延迟 200ms」只是 mock 设置，不等于加载 UI。
- 要求：在 `components.css` 增加骨架屏与按钮禁用态，写明四个页面分别在哪个请求期间切换，并说明加载态与空态的互斥关系。不写代码，只在 C 节与 D 节补文字说明。

**B3 · hidden 文件输入破坏键盘可达**

- 审议引用：B 节 1「`<input id="media-file-input" type="file" accept="audio/*,image/*" hidden />`」；同节「所有输入控件均绑定显式 `<label>` 且仅使用原生可聚焦表单控件」
- 问题：`hidden` 元素不可聚焦，与方案自身声明冲突。
- 要求：去掉 `hidden`，改用视觉隐藏但可键盘聚焦的 CSS 方案（如 clip 类），说明 `<label>` 与控件的关联方式；同步修订 B 节那句总述措辞，不要留下自相矛盾的表述。

### 三、非阻塞缺陷（5 条）

**N1 · 反馈严重度语义偏移**

- 审议引用：D 节表 2「FUTURE_TIME / CATEGORY_KIND_MISMATCH | feedback (blocking/warning)」
- 契约原文：§1.5 中 `FUTURE_TIME`、`CATEGORY_KIND_MISMATCH`、`DUPLICATE_RECORD` 三者均为 `blocking`。
- 要求：改为 `blocking`。若坚持可 `warning`，必须给出契约原文逐字引用，否则按契约改。

**N2 · 多模态入口与提交行为冲突**

- 审议引用：A 节「MVP-1（多模态对话录入）」；F 节「modality 传 "text"」
- 问题：界面提供 `voice` / `image` 选项，提交时却被强制改成 `text`。
- 要求：二选一并写清——(a) 保留实际 `modality` 值，`sourceRef` 传 `null`；(b) 明确声明多模态为降级路径，并把 A 节功能描述同步改成不承诺自动转写。禁止一处承诺、另一处降级。

**N3 · 三个表单名未登记**

- 审议引用：B 节 2「name="period"」「name="anomalyOnly"」；B 节 4「name="amountYuan"」
- 问题：三者均非契约请求参数（`/api/stats` 用 `date`/`month`/`year`；`/api/transactions` 无 `anomalyOnly`；`/api/budgets` 无 `amountYuan`）。
- 要求：在 D 节补一张「表单控件 → 请求参数」映射表：每个 `name` 是原样发送、改名后发送，还是只作本地筛选/计算不发送。若改名，写出目标参数名。

**N4 · 通用请求失败无重试路径**

- 审议引用：D 节表 1「接口失败时禁用类别筛选并 Toast 提示」
- 问题：只有失败提示，没有「重试」出口；网络抖动后用户只能刷新整页。
- 要求：补一个重试动作（Toast 动作按钮复用 `api.js` 同一方法），并写明四类接口各自的失败兜底。

**N5 · 自检口径与实例冲突**

- 审议引用：自检 11「JS 变量与函数使用 camelCase」；F 节「一张 CODE_MESSAGE_MAP 字典」「常量 USE_MOCK = true」
- 要求：二选一——把常量改为 camelCase，或在自检 11 明确「全大写常量名除外」。

### 四、不确定项 / 推断（2 条，请补充信息而非盲从）

**U1 · [推断] SVG 图表 200 行上限**

- 审议引用：G 节「仅一个双维度图表的 DOM 装配代码就会达到 150–180 行」；C 节「确保 stats.js 不超过 200 行上限」
- 问题：`chart-svg.js` 要装「柱状图与横向占比条」两种图，按其自述很可能突破 200 行。
- 要求：给出 `chart-svg.js` 的**行数拆分估算**（按函数列：坐标轴 X 行、刻度 X 行、柱体 X 行、占比条 X 行、合计 X 行）。若确实 >200，提出在不改硬约束前提下的再拆模块方案。只有团队书面裁定才能放宽到 250 行，方案本身不得单方改约束。

**U2 · [推断] 预算持久化依赖契约外写接口**

- 审议引用：F 节「点击保存时更新页面内存态并弹出 Toast 提示「当前为本地预览，待后端补充保存接口」」
- 问题：MVP-4 的持久化依赖契约里不存在的写接口，三周交付无保障。
- 要求：把 `PUT /api/budgets` 列为**联调前置依赖**写入 F 节排期，并说明若后端三周内不提供，MVP-4 的验收口径是什么（本地态演示，还是功能不算完成）。

### 五、补充观察（2 条，顺手处理）

**O1** B 节 3 只有一个 `type="month"` 输入，无法承载 `dimension=day` 所需的 `date` 参数；D 节只写「及对应日期参数」。补一个按维度切换控件类型的说明。

**O2** D 节统计降级写「柱形高度置 0 且标签显示 —」。保留标签 `—`，但把「置 0」改成「不绘制柱形」，或明确注明「0 仅为空日补值，非缺失值」，避免实现时渲染成 0 元。

### 六、交付格式

1. **开头新增「修订说明」表**，列：编号（B1/B2/B3/N1…U2/O1/O2）/ 审议结论摘要 / 你的处理（接受并改｜部分接受｜反驳｜需澄清）/ 一句理由 / 改动位置（精确到小节）。**12 条编号必须全部出现，一条不落。**
2. 其后输出**完整修订版方案**：A–G 七节标题一字不改 + 「建议新增的字段/码」+ 「自检：13 条硬约束」逐条打勾。
3. 不输出完整项目代码；骨架片段每段不超过 30 行。
4. 不得新增契约外字段；确需新增仍单列「建议新增的字段/码」。
5. 不要在方案里写「已通过审计」「符合全部约束」之类自评。
6. 若某条选择「反驳」，必须在修订说明里给出**契约原文逐字引用**或约束编号，否则视为无效反驳。
